# 微操：队伍与操作时序的联合优化

状态：2026-10-02，Draft。用户明确要求计算技能窗口附近提前或延后操作的收益。这项能力属于正式目标，不能以固定 AP、Great/Just 百分比或一个收益系数代替。

## 当前能力与时钟缺口

核心已有 raw judgement/runtime、触控候选、判定窗口和 mutable skill-window 状态。研究推荐入口主要接收声明判定流，尚无可交付的微操优化器。

当前 `live/full/mod.rs` 的 `judgement_time_ms` 用于判定转换，而 combo、life damage 与 `NoteCommand` 使用 `n.time_ms`（谱面缓存时间）。所以，不能只改 judgement timestamp 就宣布一个技能窗外 Perfect 移入窗内并涨分。最新原生必须核实：

1. 原始触控、判定产生、计分 command 和技能状态分别使用哪个时钟？
2. command 是否回溯到谱面时间，回放如何选择因子、血量与 combo？
3. 同帧 note、技能触发、condition、applier 和结算的实际顺序？
4. 提前/延后维持相同判定时是否改变收益；改变判定时净收益如何？

若某类时间移动在原生中没有收益，优化器必须返回零收益，不改变输入或数学来迎合直觉。

## 玩家决策与目标

可控决策为物理队伍 `d` 和操作策略 `π`。静态策略给出音符组的触控时间/轨迹计划；后续实时策略只能使用当时已经可见的信息，不能读取未来 RNG、未揭示技能顺序或对手结果。

默认最大化声明环境与操作误差分布下的 `E[S(d,π)]`。保留固定 AP 基线 `π₀`，展示相对收益、判定要求与容错。玩家可另选达标概率、允许误差和计划复杂度，这些目标分别计算。

原始事件表达 down/move/up/flick、触点身份、位置与时间。按键偏移与全局音画调整分开。hold/slider 的父子关系、连续轨迹、多触点和事件顺序限制使多个音符不能任意独立移动；所有约束在求值前验证。

`AutoInput.overrideDiff` 只可用于原生机制隔离实验，不能代替实际按键提前/延后，也不能直接展示成玩家操作计划。

## 搜索过程

浏览器默认不联合穷举全池队伍和全部事件的每毫秒偏移。

1. 对多个合法候选队伍完成固定打法基线。它是可行解和起点，不是微操最优上界，不能据此删除可能靠微操反超的队伍。
2. 从实际技能开始/结束、判定窗口、计分帧、撃奏区间和触控链约束生成关键时间候选；没有已验证收益因果的边界不强行制造候选。
3. 对同窗口或同触控链的音符组做有限枚举、局部搜索或 beam 提案；必要时联合多个组。combo/life/转换/累计影响后续轨迹，不能默认逐音符贪心可加。
4. 每个保留的 `d,π` 由同一个完整 evaluator、同一环境分布复算；队伍和时序轮流改进，保留多个初始队伍与重启机会。
5. 用 held-out RNG/误差样本检验收益与容错。未经可采纳上界证明标为 heuristic、gap unknown；小卡池和少数操作组用独立穷举验收。

timing policy 属于共享求值输入。DeckSearch、FixedDeck、SongRanking 均明确基线或策略；不能将隐含“逐歌最佳微操”的排行与默认 AP 的账号组卡结果直接比较。

## 验收与展示

| 用例 | 必须保留的原生证据 | 通过标准 |
|---|---|---|
| 同判定窗口前后 | 同队/共享 RNG/实际触控，原本窗外 note 提前/延后；raw event、判定/command 时间、skill state、逐帧分数 | 收益或无收益均一致，不选择更容易通过的时钟 |
| 判定取舍 | Perfect/Great/Just 边界和实际窗口/顺序 | 净收益与所需判定明确，不只算技能倍率 |
| 连续轨迹 | down/move/up/flick、父子 note、line 与多触点 | 拒绝不可执行轨迹，完整链 score/combo/life 一致 |
| 同帧与回放 | 启动/结束/延长、note、累计事件的同帧及相邻帧 | 状态、血量、舍入、回放与最终分一致 |
| 有效性 | player/frame/device 时间与 AutoInput 控制分开 | 玩家计划无实验专用输入和未来信息 |
| 搜索质量 | 小域独立穷举、联合收益反例、held-out 分布 | 覆盖队伍反超与非可加收益，不将启发式称全局最优 |

结果包含队伍、打法版本、技能/条件假设、目标音符组及位置、偏移量、可保持判定的区间、容错、基线/新分数与差值、范围和终止状态。复用既有谱面预览与卡片组件，优先突出少量可执行且收益明确的操作。

正式实现受 [M/S/B 门槛](primary-delivery-gates.md)约束。无技能 AutoPerfect 长谱、字段一致性和 WASM 编译不能单独认证微操。
